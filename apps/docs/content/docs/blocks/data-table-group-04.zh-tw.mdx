## 效能 [#performance]

這個示範把編輯模型留得很簡單：每個可編輯的 popover 儲存格各自有一個 `Popover` root。小表格要讀、測試、複製，這種形狀最容易。

關掉的 popup 通常不是成本高的地方。Popover 與 select 的內容走 portal，所以關掉時不會 mount popup DOM、listbox，也不做定位。剩下的每格成本仍是線性的：root 狀態、trigger 的處理函式、訂閱、類似 select 的控制項裡的隱藏 input，以及建立 React element。

小表格與示範用每格一個 popup root 就好。大型且沒有虛擬化的表格，先把列虛擬化。如果還是有很多可互動的儲存格，改用共用覆層：表格附近一個 popover root、多個 trigger，內容依作用中 trigger 的 payload 決定。

這些情況用共用覆層：

- 表格一次渲染很多可編輯儲存格
- popup 內容很重，或是重複的
- 儲存格要共用同一種浮動表面
- 表格已經自己持有更高層的編輯狀態

這些情況維持每格一個：

- 表格很小，或已經虛擬化
- 每個儲存格編輯器很輕
- 本地狀態比一份共用的作用中 payload 更好理解
