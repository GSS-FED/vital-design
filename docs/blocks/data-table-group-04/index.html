This block is built on the following Vital Design primitives:

  • Avatar, Calendar, Card, Editable, Popover, Table, Tag
  • CheckIcon
  • @tanstack/react-table for table state

Performance

This demo keeps the editing model simple: each editable popover cell owns its own Popover root. That is the easiest shape to read, test, and copy for small tables.

Closed popup cost is usually not the expensive part. Popover and select content is portal-based, so the popup DOM, listbox, and positioning work are not mounted while closed. The remaining per-cell cost is still linear: root state, trigger handlers, subscriptions, hidden inputs for select-like controls, and React element creation.

For small tables and demos, per-cell popup roots are fine. For large non-virtualized tables, virtualize rows first. If the table still has many interactive cells, prefer a shared overlay pattern: one popover root near the table, many triggers, and content selected from the active trigger payload.

Use the shared-overlay pattern when:

  • the table renders many editable cells at once
  • the popup content is heavy or repeated
  • cells need a consistent floating surface
  • the table already owns a higher-level editing state

Keep the per-cell pattern when:

  • the table is small or virtualized
  • each cell editor is lightweight
  • local state is easier to reason about than a shared active payload
