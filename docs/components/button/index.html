Components

Button

Trigger actions with default, text, and ghost variants, multiple themes, and icon support.

Preview

Usage

Pick a variant for the emphasis and a theme for the color. Put icons and spinners in as children; the label sizes are md and lg.

Variants

Default

The default variant renders a solid background button. It is the default rendering style. Each column shows one theme at lg and md, enabled and disabled.

Text

The text variant renders a transparent background button. Available for all themes except dangerous.

Ghost

The ghost variant renders a transparent button that surfaces a background on hover. Use it inside popovers, toolbars, and split-button menus where the surrounding chrome provides the affordance.

Sizes

Icons

Use data-icon="inline-start" or data-icon="inline-end" on child icons. Install or import the icon or spinner separately from the button.

Icon Only

For icon-only buttons, use size="icon-md" or size="icon-lg" and give the button an aria-label.

Loading State

Render a spinner as a child icon and disable the button while work is in flight.

States

Disable a button with disabled. Add focusableWhenDisabled to keep it in the tab order, for example when a tooltip explains why it is disabled.

Link

Use LinkButton for navigation that should look like a button. It renders an <a> with the same variants, themes, and sizes, and keeps link semantics, so screen readers announce it as a link and getByRole('link') finds it.

Do not use <Button nativeButton={false} render={<a />}> for links: Base UI adds role="button" to every non-<button> element.

LinkButton

Accepts variant, theme, size, className, and contentClassName like Button, plus every <a> attribute and render. It has no disabled prop, because links cannot be disabled. Render plain text or a Button instead. The root uses data-slot="link-button" and the content wrapper uses data-slot="link-button-content".

Laying out the content

Button wraps its children in a span[data-slot="button-content"] that centres the icon and label and keeps them on one line. Since that span is the button's only child, flex utilities written on the button itself have nothing to distribute — use contentClassName to reach the wrapper instead of selecting into it with [&>span]:*.

Colour, size, radius, and hover states stay owned by the theme — passing those through className will not override the variant. The button also sets overflow-hidden for its hover overlay, so a child positioned outside the button box (a notification badge at -top-1 -right-1) needs className="overflow-visible" on the button.
