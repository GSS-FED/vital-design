Toast

Status-coloured notifications dispatched imperatively from anywhere in the app.

Preview

Usage

Toast is built on Base UI's Toast. The package exports a module-level singleton toastManager and a ToastProvider that auto-mounts the viewport — drop <ToastProvider> once at the app root and call toastManager.add(...) from anywhere (event handlers, fetch interceptors, zustand actions, …). No hook required at the call site.

Status

type accepts success, warning, error, info, or loading. The toast applies the matching colour but does not pick an icon — icons are opt-in via data.icon. The loading status swaps the close X for a cancel button when data.cancelProps is supplied.

Position

ToastProvider accepts a position prop with six anchors: top-left, top-center, top-right, bottom-left, bottom-center, bottom-right. One provider serves one position — toasts dispatched through its manager render at that anchor.

Top centre

Multiple positions (two channels)

To send some toasts to one corner and others to a different corner, create a second manager with createToastManager and nest a second ToastProvider for it. Each provider/manager pair is a separate channel — pick whichever you want at the call site.

Variants

The solid variant (default) fills the toast with the status colour on a white-on-coloured layout. The subtle variant flips to a white surface with a tinted icon — matches the "notification" pattern in the design system.

Loading

For long-running operations, dispatch a toast with type: 'loading' and timeout: 0. Pair it with actionProps and a data.cancelProps button (instead of the close X) so the user can cancel the operation, then update the toast on completion.

With Icon

Pass any icon node through data.icon; the renderer drops it into the icon slot before the title.

With Description

Add a second line of context with description.

With Action

actionProps is forwarded to the action button. Use it for an "Undo" or other recovery affordance.

Promise

promise swaps a single toast through loading, success, and error states based on a promise.

Anchored toasts

For tooltip-style feedback anchored to a specific element (e.g., "Copied!" near a button), use anchoredToastManager and wrap with AnchoredToastProvider. Pass positionerProps.anchor per call.

AnchoredToastProvider

Same as ToastProvider but without position — anchored toasts position themselves against positionerProps.anchor on each call. Defaults to the anchoredToastManager singleton.

Manager methods

toastManager, anchoredToastManager, and any manager from createToastManager() expose the same imperative API.
